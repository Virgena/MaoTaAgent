---
title: 发布前自检
description: 一份逐项可勾选的插件上线检查清单
---

**读者**：准备发布插件、提交代码或交付给他人部署的人。

**结论**：逐项过完下面的清单，再运行一次 `--check` 和一次真实调用。绝大多数上线问题都能在这里提前发现。

## 协议与进程

- [ ] stdout 上没有任何非帧字节，包括依赖的打印、进度条和横幅。
- [ ] 每个请求都用同一个 `id` 回复，数字原样回显。
- [ ] 通知没有回复。
- [ ] `initialize` 回复了 `protocol: 3`。
- [ ] `initialize` 回复包含全部四项：`provides`、`injects`、`registrations`、`host_calls`。
- [ ] `provides` 里的能力与实际能处理的方法一致。
- [ ] 必需依赖写进了 `injects`，可选依赖标了 `optional: true`。
- [ ] 注册到 service 的能力也在 `provides` 里。
- [ ] 在 `shutdown` 之前不会自行退出。
- [ ] 四种 `shutdown` reason 行为一致，并且真的退出。

## 调用与流

- [ ] 普通调用返回的结果是合法 JSON。
- [ ] 未知方法返回 -32601，而不是静默忽略。
- [ ] 参数缺失或无效时返回 -32602。
- [ ] 流式回复先发 `{stream_id}`，再发 chunk。
- [ ] 终结 chunk 是 `done:true` 且 `data: null`。
- [ ] 流式错误通过 `$/stream/error` 发送，而不是普通错误响应。
- [ ] 长任务会发心跳，不会撞上 30 秒空闲超时。
- [ ] 收到 `$/cancel` 后停止发送 chunk。

## 日志与错误

- [ ] 日志走 `kernel.log` 或 stderr，绝不走 stdout。
- [ ] 错误日志带上下文：`request_id`、`capability`、`method`、`stream_id`。
- [ ] 未捕获异常会被记录，并且不会静默吞掉。
- [ ] 不依赖 `kernel_version` 开关功能。

## 配置

- [ ] 插件行只写 `command` 或 `name` 中的一个。
- [ ] 需要自定义环境变量时，使用 `${VAR}` 并确认变量已定义。
- [ ] 需要固定提供方时，在 `[capability]` 写明。
- [ ] `[plugins.<id>.config]` 的键都有文档说明。
- [ ] 需要覆盖超时或并发时，在插件行下写对应字段。

## 上线前验证

1. 运行 `--check`，确认退出码为 0。
2. 启动完整内核，确认插件出现在能力表里。
3. 发起一次普通调用，确认结果正确。
4. 发起一次流式调用，确认 chunk、终结帧和取消都正常。
5. 发送 `shutdown`，确认插件在宽限期内退出，内核退出码为 0。
6. 主观测试一次插件崩溃，确认内核没有退出，能力调用返回 -32011。

## 版本兼容

- 当前 `PROTOCOL_VERSION` 是 3。
- 协议版本通过 `initialize` 的 `params.protocol` 和 `result.protocol` 协商。
- 任一侧不匹配都会得到 -32015，启动失败。
- 新增可选字段不算不兼容，内核会忽略未知字段。
- 删除字段或改变语义属于不兼容变更，必须提升版本号。
- `kernel_version` 只用于诊断，不能用来判断能力。

## 交付物

交付插件时建议同时提供：

- 插件入口文件和构建产物。
- 一份可运行的 `[plugins.<id>]` 配置示例。
- `[plugins.<id>.config]` 的键说明。
- 需要的能力和注册关系。
- 已知限制和错误码说明。
- 日志级别和排查入口。
