---
title: 能力与路由
description: 能力表如何生成、依赖如何决定启动顺序，以及热重载换表时会发生什么
---

**读者**：维护内核路由、排查调用找不到提供方或重载异常的人。

**结论**：能力 ID 是不透明字符串，一个能力只有一个提供方。路由表由插件的 `provides` 生成，热重载时整表替换。

## 能力 ID

能力 ID 是普通字符串，例如 `demo.text`。内核不知道它的业务含义，只知道哪个插件拥有它。命名规则由插件和配置作者约定。

调用方始终按能力 ID 调用，不要缓存"哪个插件提供这个能力"。热重载会换掉整张表，缓存插件 id 会让调用指向旧世界。

## 路由表

路由表来自插件的 `provides`：

- 在 `initialize` 里声明 `provides`，能力自动进入路由表。
- 声明即可调用，不需要往配置文件里复制。
- 要退役一个能力，从配置里移除提供它的插件。
- 一个能力只有一个提供方，没有优先级、故障转移或负载均衡。

`[capability]` 只在两个插件争同一能力时用来指定提供方，见[配置与启动](/docs/blmoadll/config)。

## 依赖与启动顺序

三个声明字段决定启动顺序：

| 字段 | 含义 | 作用 |
|---|---|---|
| `injects` | 我需要另一个能力存在 | 被依赖的插件先启动 |
| `registrations` | 我把这个已提供的能力发布到某个 service | service 提供方先启动 |
| `host_calls` | 宿主会直接调用这些能力 | 只记录消费关系，不增加依赖 |

`injects` 和 `registrations` 只影响启动顺序，不限制运行时的调用权限。`host_calls` 不产生依赖，只让内核知道宿主会直接使用这些能力。

## 等待状态

如果一个插件声明的必需能力无人提供，它不会进入正常服务状态：

1. 内核仍然 spawn 并初始化它。
2. 它的 `provides` 不进入路由表。
3. 它自己的能力调用得到 -32010。
4. 依赖它的插件继续等待。
5. 内核发布 `kernel.plugin.blocked`，说明谁在等什么。

等待中的插件仍保留进程和声明。一旦提供方出现，内核会启动它。它不是提供方，所以对它的能力调用是 -32010，而不是 -32011。

`optional: true` 的注入不同：无人提供时只记警告并跳过，不阻塞启动。

## 调用方身份

调用方标签由内核写入：

- 插件调用携带插件 id。
- 宿主调用携带 `"host"`。

调用方无法自报身份，也无法冒充其他插件或宿主。

## 并发

- 每个插件 `max_inflight`，默认 64。
- 全局 `max_inflight_total`，默认 1024。
- 超过任一上限立刻返回 -32019，不排队。

内核宁可让调用方知道自己压垮了提供方，也不愿悄悄堆积请求。

## 失败与重试

- 提供方已退出：-32011。
- 提供方尚未 `start`：-32014。
- 能力无人提供，或提供方在等待状态：-32010。
- 内核不重试。重试是调用方的决定。
- 内核不做故障转移。提供方崩溃后，能力槽保留，调用继续得到 -32011。

## 热重载

热重载会替换整张路由表，而不是单条路由。

1. 内核发布 `kernel.capabilities.changed`，携带整张新表。
2. 新增或变化的插件重新走 `initialize` 和 `start`。
3. 被移除或替换的插件先排空，再收到 `shutdown{reason:"reload"}`。
4. 新配置无效时，整次重载回滚，旧配置继续运行。

插件要通过 `kernel.capabilities.changed` 更新本地快照，不要依赖启动时拿到的表。`start` 里的 `capabilities` 只是启动瞬间的快照。

如果重载让某个插件失去必需依赖，它会被停止并进入等待状态。把提供方带回来的下次重载会重新启动它。

## 重载与重启的区别

- **重载**：配置变化触发，替换整张表。内核不重启。
- **重启**：宿主点名某个插件，先停止它，再按完整流程重新启动它。

重启的停止、启动和失败处理见[进程与生命周期](/docs/blmoadll/process)。

## 事件

路由相关的事件有：

| 事件 | 含义 |
|---|---|
| `kernel.capabilities.changed` | 整张路由表被替换 |
| `kernel.config.reloaded` | 配置变更被接受 |
| `kernel.plugin.blocked` | 插件进入等待状态 |
| `kernel.plugin.started` | 插件启动完成 |
| `kernel.plugin.stopped` | 插件停止 |

主题匹配和投递规则见[事件总线](/docs/blmoadll/events)。
